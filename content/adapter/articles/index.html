MirrorPulse Adapter SDK

Adapter SDK documentation

A MirrorPulse deployment connects one configured storage root to a Worker. The same Adapter package can serve several independent deployments. MirrorPulse starts a separate process and supplies settings and credential references for each deployment.

Build your first Adapter

  1. Getting started walks through the template, the package files to edit, and the first deployment.
  2. Package configuration covers the signed manifest, the localized XML form, saved settings and credentials, authorization callbacks, health reports and version offers.
  3. Implement a Worker covers the process handshake, addresses, listing and ranged reads, uploads, mutation replay and cancellation.
  4. Test and publish an Adapter shows what the SDK runner verifies and what to check against an actual backend and MirrorPulse Host.

Protocol and API

Use the wire specification for envelope and binary field definitions, including the versioned examples beside it. Use the API reference for the .NET types that implement those contracts.

The following optional protocols require backend-specific evidence and durability. Implement ordinary file operations before assessing them.

Guide Purpose
Original directory admission Preserve the original subtree identity and the ordered, conditional plan before committing any child effect.
Original directory retirement Verify the accepted child history and retire the original directory using its retained evidence.
Atomic original directory deletion Commit and recover one qualified deletion of the whole admitted original subtree.

SDK trusted publishing is the maintainer guide for publishing the SDK and its matching wire specification and conformance tools.
